# 第 6 章　視訊通話與雙軌架構（105 秒・午後）

> 依 `06-storyboard-brief.md` 起草，格式照 `04-shotcraft-guided.md` 第 3 章樣本。
> **本章要讓觀眾記住：** 阿公按一下就能和兒子視訊；通話背後有兩條線，一條先講好怎麼連、一條專送聲音和畫面，所以鎖屏、App 關掉、換了網路都接得到。

- 時段與底色：午後（mint 偏暖、窗光斜照），承接第 5 章章尾的 mint，章尾維持午後交給第 7 章。
- 機敏資訊：全章**不出現任何網址、IP、主機名、連接埠、雲端廠商名或機房地點**。架構只用概念名稱：「信令伺服器」「影音中繼伺服器」「推播通知」。手機上的通話截圖若帶到網路狀態列或除錯訊息，一律裁掉或打碼。
- 兩條線的定色全章不變：**訊息線（信令）＝細的 App 主綠、影音線＝粗的暖橘**，觀眾靠顏色就分得出是哪一條。
- 人物呈現：通話畫面不拍真人臉。阿公那端的視訊畫面拍陽台的盆栽（換成後鏡頭），兒子那端的自拍小窗打碼或關鏡頭；頭像一律用字頭像。
- 章標籤：`06 視訊通話`。稱謂：長輩「阿公」、家屬「兒子」。

## 風險

1. **機敏資訊。** README 的架構圖、表格裡都直接寫著真實的網址、IP、連接埠和雲端機房；製作架構圖時**不能從 README 截圖或照抄**，只能照本檔的概念名稱重畫。終檢時逐格看 6-4 到 6-9、6-13 有沒有任何英數位址殘留。
2. **紅色。** 通話畫面頂部的計時膠囊裡有一顆紅色小圓點（App 原生樣式），掛斷鍵通常也是紅的。紅色只准出現在第 7 章：6-15、6-17、6-19 的截圖要後製改成主綠或深墨，掛斷鍵改成深墨底白圖示。
3. **`line-carry-transition` 全片只能用這一次**，而且線一失速觀眾就跟丟。橫移距離照卡片「1920 px／56 格」，不要提速；筆頭固定在畫面約 77% 處。卡片原本是墨色線，這裡改成主綠，要確認在 mint 底上夠清楚（線寬至少 8 px，不夠就加深一階主綠）。框閉合後筆頭要卸載，不能殘留。
4. **雙軌說明有沒有講錯。** 實際上「信令」除了約定怎麼連，也負責叫對方響（和推播互為備援）；影音在可以直連時不一定經過中繼伺服器。6-6、6-9 的畫法是「影音有一座獨立的中繼站，連不上時從它繞過去」，請組員確認這樣的簡化可以接受。
5. **6-8 掃描標註的字。** 卡片原生標籤是 32 px 等寬字，這裡是觀眾要讀的內容，標籤要放大到 ≥ 48 px、窗外標題 ≥ 60 px；放大後五個標籤會不會互相壓到要重排（卡片已知坑：標籤位置四選一，要逐個量）。卡片的「機器色」鈷藍只用在掃描線和標籤，不要混進主綠、暖橘兩條線的顏色系統。
6. **`quad-split-parallel-scenes` 給了 5.5 秒，比卡片的 3 秒長。** 前約 2.1 秒是錯拍密集段，之後四格終態停約 3 秒讓觀眾讀四個詞；不能把密集段拉長（卡片說後半會「沒東西動」）。四格內容換成 App 截圖後，錯拍時刻表要整張重排，逐格檢查沒有兩格在同一格發生重事件。
7. **三個要先確認在展示版本裡的功能：** 鎖屏全螢幕來電、App 被滑掉後推播喚起、先掛斷時對方來電同步收掉。記憶檔記錄過「鎖屏時系統自動觸發導致未經同意自動接聽」的問題；6-12 必須拍到「來電畫面等待按接聽」，不能拍到自動接起。任一項不在，四宮格那一格換成「換了網路也連得上」並刪掉對應的細看鏡頭。
8. **6-19 的頭像必須是真圓。** `circle-match-iris` 規定錨點不能是圓角方塊；通話畫面若沒有圓形頭像（目前程式裡鏡頭關閉時只有漸層背景），就用自製真圓字頭像疊上去，並在終檢時確認它不會被誤認成 App 的真實功能。圓心常數要和第 7 章 7-1 共用。
9. **6-17 的視訊畫面不拍人。** 用後鏡頭拍陽台盆栽是為了避開真人臉；若組員想用真人示範，要另外確認肖像授權。
