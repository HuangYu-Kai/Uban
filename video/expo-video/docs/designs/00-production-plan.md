## 3. 展場情境與觀眾

- **觀眾：** 評審老師、其他組同學、來賓家長（可能就是「家屬」本人）。多數人只會停留 1–3 分鐘。
- **推論 1：每一章都要能獨立看懂。** 章頭有章名卡（大字＋一句話），章內不依賴前一章才看得懂的術語。
- **推論 2：前 10 秒決定去留。** 每章的前 10 秒都放最好看的鏡頭，不放鋪陳。
- **推論 3：展場吵。** 旁白的重點必須同時出現在字幕或畫面文字上；沒有聲音也看得懂。
- **推論 4：可能是電視或投影。** 字級最小 36 px（1080p），重點字 64 px 以上；不用細線字。

## 4. 核心概念

### 4.1 一座島：Uban 島

一座等軸 2.5D 的浮空島，是全片的「地圖」。島上建築對應系統功能：

| 建築 | 對應章節 | 造型 |
|---|---|---|
| 長輩的家（有窗、有庭院、有小豬圈） | 3、4、5、11 | 兩層樓小屋，窗裡有一支手機的光 |
| 家屬的城市公寓 | 9、10 | 島另一端的高樓，窗裡有另一支手機 |
| 通話塔 | 6 | 兩條軌道從塔延伸出去：綠色（信令）、橘色（影音） |
| 守望燈塔 | 7 | 燈塔光束掃過長輩的家 |
| 地圖站（小公園＋步道） | 8 | 步道上有足跡 |
| 社群廣場（布告欄） | 10 | 大布告欄貼滿照片 |
| 營火（島中央） | 開頭、結尾、每次回島 | 配樂的視覺來源；營火的光是全片的暖光源 |

**島的成長：** 第 2 章島剛長出來，只有骨架；每看完一章，那棟建築就「點亮」。第 13 章回到島上時，整座島全部點亮。觀眾會感覺到「系統一塊一塊拼起來了」，這也是長片的進度條。

### 4.2 一顆光點：小嘎光點

- **造型：** 扁平圓形，品牌綠，帶一圈柔光；說話時圓周會出現聲波起伏。
- **規則：** 每一章都要出現；每一道接縫都由它擔任錨點（位置、大小在接縫兩側一致）。
- **形變表：** 光點 → 聲波（第 3 章）→ 對話泡泡（第 5 章）→ 電話圖示（第 6 章）→ 警示光（第 7 章）→ 地圖圖釘（第 8 章）→ 紙飛機（第 9 章）→ 照片圖釘（第 10 章）→ 胡蘿蔔（第 11 章）→ 回到光點（第 13 章）。

### 4.3 五幕結構（避免「每章都回島」的重複感）

全片不是每章都回到島上，而是分五幕。**只有換幕時回島**，幕內章節之間用光點形變直接接。這樣二十分鐘只回島 4 次，每次回島都是一個呼吸點和進度提示。

| 幕 | 章節 | 主題 | 時間 | 能量 |
|---|---|---|---|---|
| 序幕 | 0 | 60 秒廣告 | 0:00–1:00 | 高 |
| 第一幕：為什麼 | 1、2 | 問題與系統全景 | 1:00–3:30 | 低 → 中 |
| 第二幕：長輩的一天 | 3、4、5 | 小嘎、長輩 App、主動關懷 | 3:30–8:00 | 中 → 高（第 3 章）→ 中 |
| 第三幕：連在一起 | 6、7、8、9 | 通話、警報、定位、家屬端 | 8:00–14:00 | 中 → **最高（第 7 章）** → 中 |
| 第四幕：快樂的事 | 10、11 | 社群、小豬 | 14:00–16:45 | 中高、輕快 |
| 終幕 | 12、13、14 | 技術、島的一天、片尾 | 16:45–20:00 | 中 → 高（第 13 章）→ 靜 |

## 6. 鏡頭聖經

### 6.1 鏡頭動作字典（每一種動作的意義與用法）

| 動作 | 英文 | 意義 | 本片用在哪 | 緩動 | 典型時長 |
|---|---|---|---|---|---|
| 推近 | push-in／dolly-in | 聚焦、進入細節 | 進入建築窗戶、手機螢幕 | `expo.out`（強調）或 `sine.inOut`（平穩） | 0.6–1.5 秒 |
| 拉遠 | pull-out | 給脈絡、規模、結束感 | 回島、章末 | `sine.inOut` | 1.5–3 秒 |
| 橫移 | truck | 揭露、跟隨 | 手機各分頁、軌道 | `sine.inOut` | 0.5–1.2 秒 |
| 升降 | pedestal／crane | 俯瞰、權威、全局 | GPS 俯瞰、島嶼全景 | `sine.inOut` | 2–4 秒 |
| 環繞 | orbit／arc | 多面展示、時間流逝 | 第 13 章 90 度環繞 | `sine.inOut` | 4–6 秒 |
| 無限縮放 | infinite zoom | 進入另一個尺度或世界 | 窗戶→手機→介面 | `expo.in` 進、`expo.out` 出 | 1.2–2 秒 |
| 甩鏡 | whip pan | 兩地瞬間連線 | 第 9 章長輩↔家屬 | 中段速度最快＋方向模糊 | 0.3–0.5 秒 |
| 快速推近 | snap zoom／punch-in | 驚訝、強調、節拍 | 第 3、7、12 章 | `expo.out` | 0.15–0.3 秒 |
| 滑動變焦 | dolly zoom | 孤立、不安 | **全片只用一次**：第 1 章長輩獨自坐在桌前 | 線性（例外） | 3–4 秒 |
| 晃動 | shake | 緊急、慌張 | **只在第 7 章** | 噪聲，振幅 ≤ 6 px、≤ 0.6° | 0.5–1 秒 |
| 手持感 | handheld drift | 生活感、親近 | 第 1、10 章極輕微 | 低頻噪聲，振幅 ≤ 3 px | 全段 |
| 停住 | hold | 讓人讀字、讓情緒落下 | 每一個有字的畫面 | — | 字數 ÷ 5 + 0.5 秒 |

### 6.2 十二條通用規則

1. **每一個動作都要回答「為什麼動」。** 答不出來就不動。
2. **推近一次，之後橫移。** 同一個介面內，推近一次就保持在近景，用橫移看下一個功能；換場景時才拉遠。不要每個功能都「推近—拉遠」一次。
3. **讀字時鏡頭不動。** 有要讀的字時，鏡頭停住；或字放在畫面層（不隨鏡頭移動）。
4. **一次只動一個主角。** 鏡頭在動時，畫面內元素只做小動作；元素在做大動作時，鏡頭停住。
5. **前進方向固定由左往右。** 敘事往前走的橫移一律向右；回顧、回島一律用拉遠，不用向左橫移。
6. **切點放在最快的那一格。** 動作中切換，下一段從下一格接上，速度不變。
7. **緩動：** 橫移、升降、環繞用 `sine.inOut`；強調推近用 `expo.out`；元素彈入 `cubic-bezier(0.34,1.56,0.64,1)`；形變 `cubic-bezier(0.7,0,0.3,1)`。不用 `power2.inOut` 做大幅移動（起步頓挫明顯）。禁止線性，滑動變焦與機械動作例外。
8. **快速動作要有動態模糊。** 甩鏡、快速推近用 `--mb 4` 以上；平常的鏡頭動作 `--mb 2`。
9. **情緒鏡頭有配額。** 晃動只在第 7 章；滑動變焦全片一次；快速推近每章最多 3 次。
10. **第一版一定太慢。** 第一版做完，整體時間砍 20–30% 再看。
11. **三維旋轉用四元數補間，** 不用歐拉角。
12. **鏡頭動作要對到配樂。** 大的推近、拉遠的終點落在小節的第一拍；快速推近落在拍點後 2–3 格（讓畫面略晚於聲音，看起來才「對」）。

### 6.3 各風格的攝影機規格

**等軸 2.5D（第 2、6、8、13 章與所有回島段落）**

- Three.js `OrthographicCamera`，仰角 35.264°、方位角 45°，位置固定在一個「攝影機臂」上，只動臂的平移與 `camera.zoom`。
- 縮放：改 `camera.zoom` 後呼叫 `updateProjectionMatrix()`；不用把攝影機往前移（正交攝影機往前移沒有效果）。
- 平移：沿等軸方向（x、z 軸）移動，畫面上看起來是斜 30° 的移動。
- 環繞：只允許 90° 的整數倍（第 13 章用一次）。環繞時島嶼本身旋轉，比攝影機繞行更不容易穿模。
- 視差：前景雲層、島、背景星空分三層，移動比例 1：0.8：0.6。
- 禁止：透視攝影機、消失點、任意角度旋轉、傾斜（roll）。

**扁平矢量（第 4、9、14 章）**

- SVG 場景最外層包一個 `<g id="camera">`，只對它做 `transform`（translate＋scale），章節元素不碰攝影機。
- 推近到手機螢幕時，手機的外框縮放到滿版後淡出，接著介面本身成為新的「世界」。
- 置中公式：要把目標點 (x, y) 在縮放倍率 Z 下置中，平移量 = (畫面寬 / 2 − x × Z, 畫面高 / 2 − y × Z)。
- 游標或手指永遠不停：鏡頭在動時，它先往下一個目標移動 20–30%。

**Motion／動態字幕（第 3、7、12 章）**

- 二維攝影機＋節拍表；字從 0 → 1.15 → 1.0 彈出，約 8 格；逐字錯開 2 格。
- 快速推近：0.15–0.3 秒，`expo.out`，落在拍點。
- 甩鏡：方向模糊沿運動方向；中段 3–4 格幾乎全糊，切點藏在模糊裡。
- 字和鏡頭不同時做大動作。

**形變（第 5 章，及每道接縫的光點形變）**

- 鏡頭大多固定，最多一個緩慢推近（整段 3–5% 放大）。
- A → B 的形變要經過一個簡單的中間形狀（圓或膠囊）；每半段 8–12 格；加 10–15% 擠壓伸展與輕微旋轉。
- 頂點數要相同、起始頂點要對齊（用 flubber 或 MorphSVG）；交件時要附形變中段的靜態格，檢查有沒有打結。

**紙張拼貼（第 1、10、11 章）**

- 多層平面：每一層紙片放在不同 z 深度（例如背景 −400、中景 −200、前景 0、手部 +120），攝影機橫移時自然產生視差。
- **攝影機也用每秒 12 格步進**（每 2 格更新一次位置），這是定格動畫的手感；平滑的 30 fps 運鏡會破壞這個風格。
- 紙片放置抖動 ±2 px、±0.5°，每 2 格換一次隨機值（固定種子）。
- 轉場：手把紙片「啪」地貼上、翻紙、撕紙擦除。

### 6.4 攝影機工具 `shared/camera.js`（介面規格）

```js
// 建立：每章一個，依風格選模式
const cam = createCamera({ mode: 'ortho' | 'svg2d' | 'multiplane', fps: 30 });

// 關鍵格：時間（秒）、狀態、緩動
cam.key(0.0,  { x: 0, y: 0, zoom: 1.0 });
cam.key(1.2,  { x: 340, y: -80, zoom: 2.4 }, 'expo.out');
cam.hold(1.2, 3.0);                 // 停住，讀字
cam.whip(5.0, 0.4, { dx: 1920 });   // 甩鏡，自動加方向模糊

// 修飾
cam.shake(9.8, 0.8, { amp: 6, rot: 0.6, seed: 7 });   // 只有第 7 章允許
cam.step(2);                        // 拼貼章：每 2 格才更新一次

// 讀取：渲染用
cam.at(t)        // → { x, y, zoom, rot }
cam.velocity(t)  // → { vx, vy, vzoom }，接縫檢查用
cam.export()     // → 全部關鍵格，寫進該章的 camera.json
```

- `velocity(t)` 讓接縫檢查腳本可以比對接縫兩側的鏡頭速度。
- 每一章交件時要輸出 `camera.json`，組裝時拿來驗證接縫。
- 所有隨機都要有固定種子；不准用 `Math.random()` 和真實時間（渲染必須可重現）。

## 8. 接縫清單

**每一道接縫都要有一份 `seams/Jxx.json`。** 欄位：

```json
{
  "id": "J3",
  "from": "ch03", "to": "ch04",
  "global_frame": 9000,
  "type": "morph",
  "anchor": { "shape": "dot", "x": 960, "y": 540, "r": 48 },
  "camera_velocity": { "vx": 0, "vy": 0, "vzoom": -0.8 },
  "dominant_color": "brand",
  "audio": { "kind": "J-cut", "lead_ms": 500 },
  "handles": 12
}
```

| 接縫 | 從 → 到 | 轉場類型 | 錨點 | 鏡頭速度 | 備註 |
|---|---|---|---|---|---|
| J0 | 0 → 1 | P0 後決定（比對剪接或溶接） | 原片最後一格的主體 | 依原片 | 唯一不是我們控制兩側的接縫，最難 |
| J1 | 1 → 2 | 推近＋風格切換（紙 → 等軸） | 綠點 | 推近中，速度連續 | 綠點的紙紋在 6 格內淡掉 |
| J2 | 2 → 3 | 無限縮放（窗 → 手機） | 窗戶 | 推近，`expo.in` 結束於接縫 | |
| J3 | 3 → 4 | 形變（閃爍框 → 光點 → 首頁圖示） | 光點 | 靜止 | |
| J4 | 4 → 5 | 拉遠＋光點跳出 | 光點 | 拉遠中 | |
| J5 | 5 → 6 | 拉遠回島 | 荷葉／聽筒 | 拉遠中 | 回島 1 |
| J6 | 6 → 7 | 燈塔光束 → 取景框 | 光束 | 橫移 → 推近 | |
| J7 | 7 → 8 | 拉遠回島 | 光點 | 拉遠中 | |
| J8 | 8 → 9 | 形變（開關 → 紙飛機）＋跟拍 | 紙飛機 | 向右 | |
| J9 | 9 → 10 | 拉遠回島 → 推近布告欄 | 照片 | 拉遠 → 推近 | 回島 3 |
| J10 | 10 → 11 | 跟拍貼紙 | 小豬貼紙 | 向右 | 同風格，最容易 |

## 9. 段落拼接：問題與對策總表

整理自 AI 影片拼接的常見問題、剪接的連戲規則，對應到本片的程式渲染流程。

| # | 問題 | 怎麼發生 | 對策 | 怎麼檢查 |
|---|---|---|---|---|
| 1 | 色彩漂移 | 每章各自調色 | 全部讀 `tokens.json`；成片最後統一套一次調色 | 接縫兩側平均色差 ΔE < 3（同風格）／< 8（跨風格） |
| 2 | 風格漂移 | 線寬、圓角、陰影慢慢變了 | 風格聖經＋每種風格 3 張參考格 | 每章 25/50/75% 抽格與參考格並排 |
| 3 | 速度不連續 | 上一段停住、下一段從零起步 | 接縫 JSON 規定速度；切點放在最快的格 | `camera.json` 兩側速度差 < 10% |
| 4 | 跳接感 | 相似構圖直接切 | 30 度規則：景別或角度明顯不同，否則改比對剪接 | 人工 |
| 5 | 畫面方向反轉 | 上段往右、下段往左 | 前進一律向右；回顧用拉遠 | `camera.json` 檢查橫移方向 |
| 6 | 多一格、少一格、黑格、閃白 | 渲染範圍或裁切不準 | 每章前後多渲染 12 格；依接縫格號裁切 | 自動偵測黑格、全白格、重複格 |
| 7 | 音訊斷裂、爆音 | 每段配樂各自起訖 | 一條配樂主軌跨全片；旁白 J-cut／L-cut；剪點 10 ms 交叉淡化 | 頻譜圖、接縫前後 1 秒聽 |
| 8 | 與 60 秒原片接不上 | 規格、色調、節奏不同 | P0 量測原片，長片跟著它；J0 專門設計 | 接縫檢查＋人工看 |
| 9 | 編碼接縫雜訊 | 分段有損編碼後串接 | 每章輸出無失真 FFV1 中間檔，最後整片只編碼一次 | 逐格比對接縫附近 |
| 10 | 長片疲勞 | 二十分鐘同一節奏 | 五幕結構、能量曲線、回島呼吸點 | 完整觀看 |
| 11 | 中段出錯沒發現 | 只看頭尾 | 25/50/75% 抽格＋接縫前後 1 秒連播 | 檢查清單 |
| 12 | 字幕版型不一致 | 各章自己排 | 字幕獨立一層，共用一套版型 | 抽格 |
| 13 | 字型缺字 | 用到簡體字型或字型沒載入 | 繁體字型＋缺字掃描＋`document.fonts.load` 後才 `__ready` | 自動掃描 |
| 14 | 質感突變 | 紙紋、顆粒在一格內消失 | 6–12 格過渡 | 接縫前後連播 |
| 15 | 響度跳動 | 各章音量不同 | 只有一條主軌，最後統一標準化 | `ebur128` 逐秒曲線無突跳 |

| 17 | 渲染不可重現 | 用了 `Math.random()` 或真實時間 | 固定種子；同一格渲染兩次逐像素相同 | 自動：同一格渲兩次比雜湊值 |

## 10. 配樂與音效

### 10.1 方向

- 像《星際拓荒》營火旁烤棉花糖那種輕鬆、溫暖、有點懷舊的原聲民謠；斑鳩琴、口琴、鋼琴合奏。
- **版權界線：** 只取氛圍與編制，**全部原創作曲**；不用、不改編、不模仿原作的旋律、和弦進行、音色取樣。

### 10.2 樂器來源（已查 mg-styles-15 的音訊工具）

mg-styles-15 的 `lib/audio`（mgaudio）有鋼琴取樣，**沒有斑鳩琴和口琴**。它的取樣來自 VCSL（CC0），repo 只附了其中 102 個。

| 樂器 | 來源 | 授權 | 風險 |
|---|---|---|---|
| 鋼琴 | mgaudio 內建 `samples.inst('piano')` | CC0 | 低 |
| 口琴 | **VCSL 有口琴取樣**（Special 20 C、Special 20 F、Super 64），補下載進 `lib/audio/samples/` | CC0 | 中：要加氣音與輕微滑音才不會假 |
| 斑鳩琴 | VCSL 沒有。方案 A：用 mgaudio 的撥弦合成（`pluck.guitar('steel')`），調亮、縮短延音、加金屬共鳴；方案 B：找 CC0 斑鳩琴取樣 | CC0 | 高：要先做試聽 |
| 輕刷吉他、沙鈴 | mgaudio 內建 `pluck.strum`、`drums.shaker` | — | 低 |
| 營火劈啪聲 | mgaudio 沒有。用噪聲合成（隨機短促爆裂＋低頻呼呼聲），或找 CC0 錄音 | CC0 | 低 |

**試聽關卡：** P0 先做 30 秒試聽（主題前 8 小節，三件樂器合奏）。**你聽過、點頭了才量產。** 如果斑鳩琴或口琴怎麼調都假，改走備案：組員演奏錄音，或購買有公開播放授權的免版稅配樂。

### 10.3 結構

- **主題：** 8 小節主旋律，G 大調，84 BPM，帶五聲音階的民謠味。
- **一條主軌跨全片，** 20 分鐘不中斷。換章靠樂器進出與速度微調（72–96 BPM 之間平滑過渡），不靠切歌。
- **變奏表：**

| 章 | 編制 | 速度 | 情緒 |
|---|---|---|---|
| 1 | 斑鳩琴獨奏 → 加鋼琴單音 | 72 | 孤單、懷舊 |
| 2 | 斑鳩琴＋鋼琴 → 三件合奏完整主題 | 84 | 溫暖、展開 |
| 3 | 合奏＋輕打擊 | 96 | 輕快、驚喜 |
| 4 | 口琴主旋律＋斑鳩琴 | 88 | 可愛、輕鬆 |
| 5 | 鋼琴主導，口琴四小節 | 76 | 安靜、溫柔 |
| 6 | 完整合奏 | 84 | 穩定、可靠 |
| 7 | 漸弱到鋼琴單音 → 靜默 1 秒 → 慢慢回到合奏 | 84 → 自由 → 84 | 緊張 → 安心 |
| 8 | 斑鳩琴＋口琴，帶散步感 | 84 | 悠閒 |
| 9 | 合奏，甩鏡處加刷弦 | 88 | 連結 |
| 10 | 合奏最滿 | 88 | 熱鬧、幸福 |
| 11 | 斑鳩琴撥奏跳躍版 | 92 | 俏皮 |
| 12 | 合奏＋打擊 | 96 | 自信 |
| 13 | 完整合奏，最後回到斑鳩琴獨奏 | 84 → 72 | 圓滿 |
| 14 | 鋼琴收尾 | 72 | 餘韻 |

- **節拍表：** 主軌輸出一份全片的 `cues.json`，記錄每一小節、每一拍的時間；各章的鏡頭與元素動作從這裡讀拍點。
- **混音：** 旁白出現時配樂自動壓低 8–10 dB（側鏈壓縮）；全片 −14 LUFS、真峰值 ≤ −1 dBTP。

### 10.4 音效

- 紙張：貼上、翻紙、撕紙（拼貼章）。
- 等軸：地磚落下的木頭聲、建築長出的「咚」。
- Motion：字彈出的短促「啵」、甩鏡的呼嘯。
- 警報：第 7 章唯一一次警示音，音量克制。
- 所有音效用 mgaudio 合成，或 CC0 素材並記錄來源。

## 11. 旁白與字幕

- **字數預算：** 20 分鐘扣掉開場 60 秒、純音樂段落約 3 分鐘，旁白約 16 分鐘；以每分鐘 230 字計，**約 3,700 字**。各章字數依該章時長分配（例如第 4 章 105 秒 × 0.8 旁白比例 × 3.8 字／秒 ≈ 320 字）。
- **語氣：** 溫暖、口語、不炫技；技術名詞（第 12 章除外）一律換成白話。
- **時間碼：** 旁白錄好之後，用語音辨識自動對齊出每一句的起訖時間，寫進 `narration.json`；字幕與畫面的停留時間都從這裡讀。
- **字幕：** 每行 ≤ 16 字，最多兩行；Noto Sans TC Medium，白字＋半透明深底；畫面下方 12% 字幕區。
- **流程：** P2 先寫完整腳本給你看 → 你確認 → 錄音或合成 → 對齊 → 才開始各章的精確時間調整。**各章畫面可以先用暫時旁白（TTS）做，正式錄音進來後再微調。**

### 12.2 每章的頁面合約（沿用 mg-styles-15）

```js
window.DEMO = { width: 1920, height: 1080, fps: 30, duration: 90,
                motionBlur: { samples: 2, shutter: 0.5 } };
window.renderAt = async (t) => { /* 依時間 t（秒）畫出那一格，不得依賴前一格 */ };
// 字型載入完、場景暖機完：
window.__ready = true;
```

- `renderAt(t)` 必須是**純函式**：只看 `t`，同一個 `t` 永遠畫出同一格。
- 每章的 `duration` = 章長＋前後各 12 格把手。
- 禁止 `Math.random()`、`Date.now()`、CSS transition；隨機一律用固定種子。

### 12.3 全片時間軸 `timeline.json`

```json
{
  "fps": 30,
  "chapters": [
    { "id": "ch00", "src": "C:/Users/kevin/Downloads/ad_60s.mp4", "in": 0, "out": 1800 },
    { "id": "ch01", "dir": "chapters/ch01-collage", "in": 1800, "out": 4500, "handles": 12 },
    …
  ]
}
```

組裝腳本只看這一份，章節長度改動時只改這裡。

### 12.4 渲染器的 Windows 調整（讀過原始碼後確認要改的地方）

| # | 原始碼的問題 | 調整 |
|---|---|---|
| W1 | Chrome 預設是 macOS 路徑 | 設環境變數 `MG_CHROME=C:\Program Files\Google\Chrome\Application\chrome.exe` |
| W2 | 非 macOS 的 GPU 參數是 Linux 的 `gl-egl` | 設 `MG_GPU_ARGS=--use-angle=d3d11`，先試；不行再用軟體渲染 |
| W3 | 渲染槽位鎖寫死 `/tmp/mg-render-slots` | 改成 `os.tmpdir()` |
| W4 | ffmpeg 串接清單寫 Windows 路徑，反斜線可能被當成跳脫字元 | 寫清單前把路徑換成正斜線 |
| W5 | 章節路徑含反斜線，被放進網址 | 轉成正斜線 |
| W6 | 預設 10 秒、單一輸出 | 用 `--duration`、`--from/--to`、`--mkv`（無失真 FFV1）輸出中間檔 |

**備案：** 如果 Windows 怎麼調都不穩，改在 WSL2 裡跑（原始碼本來就在 Linux 上驗證過）。

### 12.5 渲染預算估算

| 項目 | 數字 |
|---|---|
| 總格數 | 19 分鐘（不含原片）× 60 × 30 ≈ **34,200 格** |
| 動態模糊取樣 | 平均約 2 倍 → 約 68,000 次擷取 |
| 單次擷取 | 1080p 約 0.15–0.5 秒（依場景複雜度） |
| 單機 3 個平行工作 | 全片完整渲染一次約 **1–3 小時** |
| 中間檔大小 | FFV1 1080p 約 30–60 Mbps → 全片約 **5–9 GB** |
| 預覽 | `--scale 0.5`、`--mb 1`，速度約快 6–8 倍，日常檢查都用預覽 |

### 12.6 組裝流程

1. 每章用 `--mkv` 輸出無失真中間檔。
2. `assemble.py` 依 `timeline.json` 裁掉把手，依序串接（原片先轉成相同規格的無失真中間檔）。
3. 疊全片統一的顆粒與調色。
4. 混入配樂主軌、旁白、音效，標準化響度。
5. **整片只做一次有損編碼**：H.264、CRF 14、yuv420p、BT.709、AAC 320k、48 kHz。
6. 執行全部檢查工具，產出報告。
