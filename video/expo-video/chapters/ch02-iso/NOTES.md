# 第 2 章 進入 Uban 島（等軸 2.5D，60 秒，60 fps）

交件：`out/ch02.mkv`（1920×1080、60 fps、3600 格、ffv1）、`camera.json`、`js/island_home.json`（ISLAND_HOME）。
重新輸出 camera.json：`node chapters/ch02-iso/js/export_camera.mjs`。

## 技術
- Three.js 正交攝影機（方位 45°、仰角 35.264°，位置 = 目標 + (1,1,1)/√3 × 80），只動「臂的平移 (x,y)」與 `camera.zoom`。zoom=1 時畫面寬 18.7 世界單位。
- camera.json 的 x、y 是臂在影像平面上的平移（世界單位；x 沿 (1,0,-1)/√2、y 沿 (-1,2,-1)/√6），用共用 `createCamera` 存關鍵格。
- 三面明暗：`geo.js` 自建幾何，軸向面直接用 `isoFaces()`，斜面（屋頂、圓柱）依法線混合三面色。全部 MeshBasicMaterial 頂點色，沒有燈光；雲才用 Lambert＋半球光。
- 光點、光線、流動光點、標籤、營火柔光、火星都在 SVG 疊層，每格自己把世界座標投影成螢幕座標（含島 ±3° 旋轉）。
- 接觸陰影：地面上的柔邊貼圖（canvas 模糊矩形／圓）。

## ISLAND_HOME
`{ x: 0, y: -0.7, zoom: 0.64, rotY: 0 }`（`js/island_home.json`）。之後回島：把攝影機臂設成 x、y、zoom 即可，島旋轉 0。注意：實際取值 zoom 0.64 與計畫書的 0.7 不同，因為本章 zoom 以「畫面寬 18.7 單位」為 1，數字不能直接對照。

## 已知問題
- 同一個 t 在「單獨渲染」時 PNG 雜湊完全相同；但在「同一次連續抽格」序列中，雲層邊緣偶有 ≤123 像素、色差 ≤5 的差異（疑似 GPU 抗鋸齒／雲球交疊深度，與前一格渲染歷史有關）。肉眼不可見。
- 計畫書 2-5 的 zoom 數字（1.2 → 0.7）是示意，本章實際是 0.7 → 0.64（見上），構圖以 ISLAND_HOME 為準。
- 前景雲層的 1:0.8:0.6 視差：Three 正交下平移是各層等量，只做了雲層整層跟隨攝影機 20%，沒有獨立的前景高雲（做過，會擋住建築，已拿掉）。
- 標籤斜切只有 −20°（不是 ±30°）：±30° 的 64 px 標籤垂直落差太大，會裁到畫面外。「小嘎 AI 助理」標籤不斜切。
- 計畫書說「每棟長出時對一個鋼琴音」：本章只提供時間點（見鏡頭表），音訊由音樂部門處理。
- shared/ 沒有發現需要繞過的 bug。
- 錯誤紀錄：`dot.js` 的光點在 SVG 內，位置每格由章節程式投影，島旋轉時光點中心固定在 (0,hover,0)（旋轉軸上），不會晃。
