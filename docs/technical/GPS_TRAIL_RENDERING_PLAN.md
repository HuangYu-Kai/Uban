# GPS 移動軌跡呈現改善計畫

> 建立：2026-09-30 ・ 分支：`feat/gps-location` ・ 狀態：**第一階段已實作（2026-09-30），第二階段待做**
> 相關檔案：`mobile_app/lib/services/elder_location_service.dart`（長輩端採集）、
> `mobile_app/lib/screens/family/elder_location_map_screen.dart`（家屬端呈現）、
> `uban-api/routers/location.py`（儲存與查詢）

## 1. 現況問題（2026-09-30 實機截圖，王小蛙，杭州南路／忠孝東路一帶）

| # | 看到的現象 | 根因（對照程式碼） |
|---|-----------|-------------------|
| P1 | 同一段路出現多條來回重疊的尖刺線 | 採集端只擋 `accuracy > 50m`；精確度 30–50m 的漂移點全部被接受。`distanceFilter` 30m 小於允許的誤差，**靜止在室內時的漂移本身就會觸發回報**。 |
| P2 | 線條直接斜切穿過街廓與建築 | 取樣間隔 `_reportInterval = 60s`：步行約 80m 才一個點，轉角全被抄成直線。 |
| P3 | 從畫面外拉進來一條長直線 | 前端把整天所有點串成**一條** `Polyline`，中間斷訊、App 被殺、關閉分享造成的空白時段，也被直線連起來，看起來像真的走過。 |
| P4 | 跳點過濾實際上沒作用 | `_onPosition` 只在 `elapsed < 10s` 時丟棄 >300m 的跳躍，但取樣間隔是 60s，**條件幾乎不可能成立**。 |
| P5 | 看不出先後順序、在哪裡停留、停多久 | 單色單線、沒有起點與停留標記；初始鏡頭只對準目前位置，沒有框住整段軌跡。 |

## 2. 原則

- **原始資料照存、不在寫入端修改**：後端 `elder_location_ping` 保留原始點（稽核、日後調參都需要）；清理與簡化在**讀取端**處理。
- 採集端只做「明顯無效點」的丟棄，並把取樣調密一點，讓讀取端有足夠的資料可以清理。
- 先不做道路吸附（map matching）：需要外部服務（OSRM／Mapbox），會把長輩的位置送到第三方，跟剛改好的隱私權政策「不提供第三方」衝突。列為第四階段，另外評估。

## 3. 分階段計畫

### 第一階段：家屬端呈現（純前端，先做，效果最明顯）

新增 `lib/services/location_trail_processor.dart`（純函式，不碰 UI，方便單元測試），把 `/trail` 回傳的點依序處理：

1. **速度離群點剔除**：相鄰兩點的推算速度 > 40 m/s 就丟棄該點；「A→B→C 中 B 離得很遠但 A≈C」的尖刺也一併剔除（解決 P1、P4 的殘留）。
2. **依精確度加權**：`accuracy_m > 35` 的點只拿來判斷是否停留，不畫進線裡。
3. **分段**：相鄰兩點間隔 > 10 分鐘，**或**距離 > 500m 且推算速度不合理時，斷成新的一段。每段是獨立的 `Polyline`；段與段之間**不畫線**，或畫淡色虛線並標示「此段無訊號」（解決 P3）。
4. **停留點偵測**：半徑 50m 內停留 ≥ 5 分鐘的連續點合併成一個「停留」標記（顯示 `14:05–14:40 停留 35 分`），停留期間的漂移點不畫線（解決 P1 的主因）。
5. **簡化**：用 Douglas-Peucker（容差約 8m）減少點數，讓線條平順，也降低一整天數千點的繪製成本。

`elder_location_map_screen.dart` 呈現調整（解決 P5）：

- 起點標記（綠點＋時間）、停留標記（可點開看時段）、目前位置維持紅色圖釘。
- 線條加白色外框（`borderStrokeWidth`）提高對比；依時間由淺到深漸層，或每隔一段距離加方向箭頭。
- 初始鏡頭改用 `CameraFit.bounds` 框住當天整段軌跡；右下角加「回到目前位置」按鈕。
- 底部資訊列加上當日摘要：總移動距離、外出時段、停留地點數。

### 第二階段：長輩端採集品質

`elder_location_service.dart`：

- `_maxAccuracyMeters` 50 → 30（Android 在戶外通常 < 15m）。
- 跳躍過濾改成以**速度**判斷（距離 ÷ 經過時間 > 40 m/s 就丟棄），不再用 10 秒門檻（修 P4）。
- 靜止抑制：新點與上一個接受的點距離小於 `max(accuracy, 20m)` 時不回報，但每 5 分鐘至少送一次心跳點，確保「最後更新」不會變成已過期。
- 移動時取樣加密：`intervalDuration` 60s → 15s、`distanceFilter` 30m → 15m（解決 P2）。
  - ⚠️ 耗電：需要實機量測一小時的耗電差異再決定最終數值；超過可接受範圍的話，改成依速度自動調整（靜止 60s／移動 15s）。

### 第三階段：後端（視需要）

- 若第一階段在點數多時前端太慢，把處理器移到後端，新增 `GET /trail?simplified=1` 直接回傳分段、停留點與摘要；原始點的端點保留不變。
- `recorded_at` 索引已存在（`idx_location_ping_elder_time`），查詢不需要調整。

### 第四階段（另案評估）：道路吸附

- 自架 OSRM `match` 服務（資料不出自家機器），或第三方 API（需要修改隱私權政策並升版）。
- 前三階段完成後，如果斜切問題仍然明顯才考慮。
