## 一、最重要的一件事：正式環境現在是壞的

**症狀**：App 連不到後端，任何需要連線的功能都無法使用。

**根因**：那台 Fedora 主機的 **Tailscale 節點金鑰已過期**。
`tailscale ping 100.73.39.14` 回 peer's node key has expired，
App 的連線入口 `https://localhost-0.tail5abf5e.ts.net/` 也完全連不上。

**連帶影響（很重要）**：
- 本輪的 8 個 commit **已經在 `origin/main` 上**（不是我推的）。
- 但部署流程是「推 `main` → GitHub Actions → 透過 Tailscale 連進主機 → SSH 執行部署」
  （`.github/workflows/deploy.yml`）。主機的 Tailscale 斷線時，SSH 那一步會失敗。
- **所以正式環境跑的很可能仍是舊版程式**。這台開發機沒有 `gh` 指令、repo 又是私有的，
  我無法直接查 GitHub Actions 的結果——請你到 Actions 頁面確認那次部署是成功還是失敗。

**修復步驟**：
1. 請主機管理者在那台 Fedora 主機上執行 `sudo tailscale up` 重新登入。
2. 到 Tailscale 管理後台，對這台機器選 **Disable key expiry**（否則過一陣子又會過期）。
3. 確認 `https://localhost-0.tail5abf5e.ts.net/` 連得上。
4. 到 GitHub Actions 重跑部署 workflow（或再推一次 `main`），確認這次真的部署成功。
5. 之後才有辦法做第四節的實機測試與第五節的資料庫清理。

### 2. 幽靈帳號 ✅（資料清理待授權）
- 根因：後端建立自主長輩帳號時，姓名預設值是 `"長輩朋友"`，而前端從來沒傳過姓名——
  預設值被當成真名寫進資料庫。這就是正式庫那些「長輩朋友」與「0.0」帳號的來源。
- 改為**姓名必填**＋基本格式檢查（至少要有一個文字，擋掉「0.0」這類），不合格直接擋下並顯示原因。
- 移除「登入宇璿」測試按鍵，以及「沒有 session 就自動登入宇璿」的退路。
- 移除兩支**不需登入就能建立／改寫帳號**的測試端點（其中一支還寫死綁定到 BoYo 帳號），
  以及前端四個已經沒人呼叫的死程式碼。
- 沙盒（自動化測試工具，正是幽靈帳號的製造機）加上防呆：如果它要開的網頁是指向**正式站**的建置，
  直接拒絕啟動；連判斷不出來也拒絕。

### 3. 長輩端家人綁定 ✅
- 根因：長輩從「我的」分頁開配對對話框時，程式沒有把長輩身分傳進去，對話框只能用兩個備用鍵去猜；
  兩個都讀不到時身分是空的，後端卻照樣回一組看起來正常的配對碼。家屬確認時，後端因為這組碼沒有建立者，
  把它當成「新長輩註冊」，於是建出一個長輩看不到的幽靈帳號，家屬被綁到那個幽靈上。
  **沒有錯誤訊息、沒有當機，綁定就是沒發生。**
- 改為明確傳入身分；真的讀不到就直接顯示「無法確認您的帳號，請重新登入後再試」，
  不呼叫後端、也不給重試鍵（這種失敗重試不會好）。

### 8. AI 語音觸發 ⚠️ 部分完成
- ✅ **語音撥號**：喚醒詞打開的浮層原本完全不解析動作標記（連既有的影片標記都會被原文唸出來）。
  現在可以「幫我打電話給家人」與「幫我打電話給〇〇〇（好友）」，同名好友會誠實反問是哪一位。
- ✅ **確認語的安全網**：原本設計是「唸完確認語才跳到撥號畫面」，讓長輩來得及喊停，
  但語音套件在預設設定下「一開始唸就返回」，畫面在長輩聽到之前就跳走了；
  而直接打開等待完成的開關更糟——語音一出錯就永遠不返回、撥號卡死。
  改為同時掛完成與錯誤兩個處理器，再加 8 秒逾時兜底。
- ✅ **家屬端語音排程（本輪新增）**：家屬的排程助理加上麥克風按鈕，
  講完轉成文字填進輸入框，**不會自動送出**——語音會聽錯，必須讓家屬看過再按送出。
- 🚨 **意外發現：這支排程助理的後端其實一直是壞的**。三個各自獨立的錯誤疊在一起
  （缺少模組引入、查詢用了不存在的欄位名、回應函式傳了不存在的參數），
  導致**任何請求都會失敗**。家屬過去看到的「近況速報」100% 是前端自己編的假資料，
  排程的語意解析也一直是前端的正則表達式在撐（建立提醒本身有真的寫進資料庫，
  所以功能表面上可用，但 AI 解析從未真正跑過）。三個錯誤本輪都已修好，
  後端現在真的會執行——這也是為什麼下一項（授權檢查）必須一起補。
- ❌ **長輩端語音排行程未做**：長輩端的工具清單裡沒有「建立提醒」這個工具，

### 12. 警報狀態機 ✅
- 根因：「確認警報」的端點在本輪之前**呼叫次數是 0**，所以每一筆警報永遠停在「待處理」，

- 第二個根因：同一警報每次重新偵測都會把「偵測時間」洗成現在，
  **持續發生中的跌倒（最該升級的情境）永遠不會老化**。因此新增「首次偵測時間」欄位，
  只在真正新建時寫入，作為 2 小時逾時判斷的唯一起算點。
- 依你的裁示實作：待處理每 **10 分鐘**重推一次、處理中**照樣計時**、
  從首次偵測滿 **2 小時**升級給開發者主控台、處理中閒置 **20 分鐘**退回待處理、
  **不做任何電話號碼設計**。
- 家屬端新增「回報已處理」按鈕；誤報會連動結案。
- 開發者主控台新增決策視窗：聯絡家屬（立即重推）／建議報醫（只記錄，並附長輩地址與家屬聯絡方式，
  且明講系統沒有留存電話號碼）／結案。
- 依你的裁示，**舊警報在新版第一次啟動時會一次性自動結案**，標記為「舊警報，系統自動結案」，
  不推播、不升級、不計入風險分級，而且在家屬端不會顯示成「家屬已處理」。
  ⚠️ 這是**不可逆**的資料變更，會在部署後的第一次啟動自動發生。
- 誠實性：重推通知會回傳實際送出的裝置數，**0 個對象時主控台會明講「沒有可推播的家屬裝置」**，

## 三、本輪額外修復（不在 14 項需求內，是查證時發現的）

1. 🚨 **資料外洩**：查詢長輩活動紀錄的端點，沒帶家屬 id 就**完全跳過綁定檢查**；
   解析不到長輩時會 fallback 成「全系統最新建立的那位長輩」，再不行就寫死一個 id，
   然後回傳那位長輩的完整活動紀錄。合法家屬**打錯一個字**就會看到陌生長輩的紀錄。已改為查不到就回 404。
2. **用藥打卡會假裝成功**：三個打卡入口中有兩個連後端回傳值都不等，
   API 失敗照樣在本機寫入「已完成」，三個畫面一起顯示已完成——長輩反而比修之前更無從察覺。
   已改為失敗時回退，並收回小豬已經講出口的「打卡成功」台詞。
3. **健康與情緒圖表全是假資料**：心率／血壓／血糖全庫零欄位，改為保留版面顯示「--」且不畫任何曲線；
   身高體重新增時間序資料表真實串接；情緒改為「近期負面情緒關注事件」列表
   （系統只在偵測到難過或生氣時才記錄，連續曲線在資料上不可能成立）。假資料產生器整個刪除。
4. **家屬問「長輩今天過得怎麼樣」，回答是編的**：心情分數、用藥狀態、活動狀態全部由模型自由發揮，
   備援路徑甚至直接寫死「今日用藥全數完成」「正在客廳休息放鬆」、心情 90 分。
   已改為先查真實資料、由程式組出內容、模型只負責轉述；查不到就明講沒有紀錄，心情分數整個移除。
5. **長輩講完電話後，首頁就收不到主動關懷**：通話畫面關閉時會把首頁剛重新綁定好的回呼清掉
   （違反既有護欄），直到 App 重啟為止。已依護欄改為「確認仍是自己掛上去的才清除」。
6. **背景推播文字不分類型**：長輩開口求救時，家屬在背景收到的通知寫的是「偵測到跌倒、請查看監視畫面」——
   語音求救根本沒有監視畫面。已改為六種類型 × 首次／提醒共 12 組文案。
7. **測試預設不安全**：專案的測試設定會連到正式資料庫（`.env` 指向正式庫，
   而且有一個每個測試都會自動執行的清理步驟會下 DELETE）。已改為預設只碰本機備援資料庫。
8. **備份檔含密碼雜湊**：把備份目錄加入 `.gitignore`，避免被提交。
   （已查證：該備份從未進過版控，不需要輪替任何金鑰，這一行是預防性的。）
9. **家屬排程助理的後端從來沒真正跑過**：三個獨立錯誤讓它對所有請求都失敗（詳見第二節第 8 項）。
   修好之後**立刻補上家屬綁定驗證**——因為在修好之前它不會回傳任何東西，
   修好之後它會真的回傳長輩的用藥打卡次數、負面情緒事件、步數與下一筆提醒，
   而原本的程式沒有檢查請求者是不是這位長輩的家屬，前端甚至把家屬身分寫死成 `1`。
   這個洞是本輪自己造成的，所以本輪一起補：無綁定關係回 404，讀不到家屬身分就不送出請求。
